# Fitted surface cave meshes

The final `Native Fitted Stone` shader calculates texture UV from interpolated world position in the fragment shader: `worldXY * _PixelsPerUnit / _NativeTextureSize`. This avoids unstable baked UV differences on very thin clipped triangles. Native source dimensions are explicit, so platform import resizing does not alter the authored world footprint. `WorldRefreshTrimSilhouette.ConfigureWorldUVMaterials()` updates the generated materials and writes `trim_world_uv_materials.json`; it changes no geometry. The density auditor must evaluate this shader's actual world mapping analytically, then apply the imported/source dimension ratio for the import-density check. The mesh's retained UV0 is no longer sampled by this shader.

`WorldRefreshTrimDensity.ApplyCurrent()` is a serial Editor entry point for the currently open, saved upper scene. Run after `WorldRefreshSurface.ApplyCurrent()` and the new region texture imports. It never opens scenes or invokes retired builders.

It measures every eligible static fitted-passage triangle using the maximum singular value of the world-distance/native-texel transform at the closest authored orthographic camera. Only failing meshes change. Each repair receives a new mesh and material under `Assets/Development/Layouts/WorldRefresh_20261104/NativeTrim/MRxx/`. Source meshes, materials and images remain untouched.

Solid outer walls and recessed inner walls tile the region Fill at 360 pixels/world-unit (the accepted Cradle Fill remains 240). Native walking strips and roof meshes sourced from a top strip retain their original walking-line registration. The original UV encodes distance from the 0.8-unit walk row. New top mapping uses the measured region source row; its frequency increases if the exact triangle audit requires it. Vertex positions, triangles, colors and all secondary UV channels remain identical, and the serialized collider collection must remain identical before saving.

The default preserves roof pieces sourced from alpha-shaped corners, steps and cliff faces. Turning those rectangular meshes into solid stone would expose pixels that were formerly transparent. `ApplyCurrent(true)` explicitly allows that replacement for a separate visual review; it preserves physical geometry but changes the visible outline. The receipt names every retained piece.

The original `_EdgeMask` texture remains on fitted-wall materials. In particular, `Cave Rollout Surface Rim` samples both its alpha and its RGB around the cave mouth. The MainTex density result does **not** certify those secondary samples. A full all-environment 4K claim requires auditing/replacing that mapping too. Inner Wall uses that secondary image only as an aperture contour mask.

The static meshes have no local runtime behavior. Their parent cave data/threshold components control traversal and player emergence, not mesh or material reconstruction. The existing cave depth script updates sprite renderers rather than these mesh renderers.

Application writes `MRxx_trim_density.json`. Parent integration is responsible for compilation, scene execution, cave-mouth screenshots and the final whole-scene density audit. No Editor execution or platform testing was performed by the surface-authoring agent.

## Native silhouette completion pass

Run `WorldRefreshTrimSilhouette.ApplyCurrent()` after the conservative density pass. This resolves the corner and secondary-mask limitation above without making the old rectangular meshes opaque. It reads the accepted image alpha into temporary memory and reconstructs the 50% alpha contour as actual triangle geometry. Fully solid interiors remain coarse; only boundary triangles refine, starting with a boundary-triangle edge limit of four screen pixels at the closest 4K camera and bilinear interpolation of the contour crossing. If a trim or complete doorway exceeds its triangle budget, the builder retries automatically at 4.5, 5, 6, 8, 12, 16, 24 and at most 32 pixels, stopping at the first passing tier. The receipt records the actual achieved contour precision for every mesh; texture color density stays native throughout. The original image is never modified or enlarged.

The new shader samples only the region's native Fill. It retains vertex shading, the existing terrain-boundary clip channel, interior tint and top fade. It does not sample an old rim image, either for color or alpha. New visible edges follow the original silhouette, made crisp through geometry; this does not invent additional silhouette detail. Physical colliders, doorways and arrivals remain unchanged. Interpolated vertices lie on their original mesh triangles, though transparent regions are now absent from the render mesh.

`MRxx_trim_silhouettes.json` records the source alpha, before/after triangle counts, maximum boundary triangle size in screen pixels and native texture requirements. Parent must inspect cave-mouth appearance and assess the added triangles; the compact pass welds shared vertices, retains only shader-used channels, packs vertex color, and currently enforces 5,000 triangles per corner trim / 20,000 per fitted wall and 40,000 total visible triangles per fitted doorway. Per-door totals and hardware performance still require review. Run it with the default conservative density pass; do not first replace alpha trim with opaque rectangles.

## Decorative grounding and Cradle exceptions

WorldRefreshDecorGrounding.ApplyCurrent() rechecks static ground decorations against the preserved pre-change scene by original transform file ID. Hanging ivy/roots use the original upper riser lip, retaining their top inset, flip and scale. Ordinary plants use their original floor attachment. The target is recomputed from original position, so repeated runs do not accumulate offsets. Collider-bearing objects, gameplay scripts and unrecognized scenery remain untouched. MRxx_decor_grounding.json lists moved, already-aligned and retained candidates.

WorldRefreshSurface.RetireWeakCradleOverlaysCurrent() suppresses only Cliff corners (R) on route piece 00 and Step 253.6 inner on route piece 01. Those two overlays fell below 216 PPU after existing deformation. The accepted native top/fill remain underneath; every other Cradle kit field remains intact. Clearing individual kit sprite fields would disable the entire kit and is deliberately avoided.
